# Flying Bird v2.5 — Multiplayer Cosmetics

## Что изменено
- В онлайн-гонке каждый участник видит **экипированный скин** остальных игроков (не скин их аватара профиля).
- У каждого игрока отображается **его выбранный след**: Fire, Water, Lightning, Rainbow, Nature, Golden, Frost, Stardust, Shadow, Aurora и Hearts.
- Используется существующий рендерер моделей и следов одиночного режима; птицы соперников по-прежнему полупрозрачные.
- Отправляются только два небольших значения (`skin` и `trail`), **один раз за матч**. Координаты передаются прежним способом — дополнительного потока эффектов через Firebase нет.
- Внешний вид фиксируется при подключении к новому матчу; изменение экипировки во время гонки не допускается.
- Одиночные сохранения, монеты и инвентарь не изменяются.

## ВАЖНО: обновить правила Firebase ПЕРЕД кодом

1. Открой Firebase Console → **Realtime Database → Rules**.
2. Сохрани резервную копию действующих правил.
3. Открой `firebase-rules/Flying_Bird_RTDB_v2_5_FULL.json` и вставь всё его содержимое в редактор Rules.
4. Нажми **Publish**. Это полная версия правил, основанная на правилах Multiplayer Update 2, с новым разрешением на `multiplayerMatches/$code/cosmetics/$uid`. `presence` и `presenceAccess` сохранены.
5. Если текущие опубликованные правила у тебя уже отличаются от ранее выданной версии, сначала сравни их — не затирай более новые ограничения. Новая секция находится внутри `multiplayerMatches/$code`.

Почему это нужно: пользователь должен иметь право записать **свой** набор `{skin: 10, trail: 'FIRE'}` один раз до времени старта. Без нового разрешения игра продолжит запускать матч, но появится `COSMETICS_SYNC · PERMISSION_DENIED`, и другие игроки могут увидеть базовые модели.

Правила не могут проверить, действительно ли предмет куплен: они ограничивают формат, срок записи и UID. Подтверждение владения на сервере относится к будущему anti-cheat этапу.

## Установка файлов

ZIP содержит только:

- `src/multiplayer/multiplayer.js`
- `package.json`
- `firebase-rules/Flying_Bird_RTDB_v2_5_FULL.json` (для установки в Firebase Console)
- `README_UPDATE_v2_5.md`

**`src/config/runtime.js` отсутствует в архиве и не перезаписывается.**

В терминале Mac:

```bash
cd ~/Flappy-bird
cp -R ~/Flappy-bird ~/Flappy-bird-backup-v2.4
unzip -o ~/Downloads/Flying_Bird_v2_5_Multiplayer_Cosmetics_Update.zip -d ~/Flappy-bird
npm run check
git add src/multiplayer/multiplayer.js package.json firebase-rules/Flying_Bird_RTDB_v2_5_FULL.json README_UPDATE_v2_5.md
git commit -m "Flying Bird v2.5 - multiplayer cosmetics"
git push origin main
```

Проверь, что Render публикует `main` из корня репозитория (`Publish Directory = .`).

## Проверка на двух устройствах

1. Оба игрока должны открыть новую опубликованную версию. На первом выбери, например, **Phoenix + Fire**, на втором — **Royal Raven + Aurora** (если предметы куплены).
2. Создай **новую** комнату. Оба нажимают Ready; хозяин начинает матч.
3. Во время обратного отсчёта должна появиться косметика соперников. После старта оба должны видеть выбранные модель и след другого игрока, а не скин аватара.
4. Повтори проверку на портретном телефоне и ПК / Landscape.
5. Проверь обратную совместимость: если у игрока нет выбранного следа, должна отображаться птица без следа.

## Что проверено в сборке

- Проверка синтаксиса всех 7 JavaScript-файлов (`npm run check`) — ОК.
- Unit-тест определения экипировки, неизвестных значений и недоступного следа — ОК.
- Статические проверки ограничений RTDB — ОК.
- Chromium: оригинальный рендерер нарисовал два различных скина и следа на одной сцене на трёх размерах экранов — ОК.
- **Не проверено:** компиляция правил непосредственно в Firebase Console и обмен косметикой между двумя реальными устройствами.

Правила **обязательно публикуются вручную**, коммит JSON в GitHub сам по себе не обновляет безопасность Firebase.
